# 音频对齐为什么会失败：一个 DSP 算子的设计、测试与消融

> **v0.6.0 集成说明：** 整数延迟算子现已接入比较页的 **Align**。用户确认应用后，播放、分析和导出使用可重置的会话副本。下文保留研究阶段的实验过程与计时，不代表完整插件的性能。参见[当前用法与限制](../audio-alignment.md)和[研究源码获取说明](audio-alignment-research.md)。

> English: [Building an Audio Alignment Operator: Design, Failures, and Ablation](audio-alignment-dsp.en.md)
>
> 2026-10-17 · EAR Audio Preview 研发记录。本文实验记录独立研究分支中的整数固定延迟原型，实验发生在产品集成之前；v0.6.0 的集成状态见上方说明。所有性能数字均来自 Apple M5 Pro、Node.js v24.9.0 和本文说明的固定输入。

比较两个音频文件时，我们常常想回答一个很具体的问题：它们是否只是晚了几个采样点、响了一些，或者整体反了极性？把这些差异补偿后，还剩多少真正不同的声音？

互相关能给出一个起点，但“找到最大的相关峰”还不够。左右声道可能在混合时相消，正确峰可能是负的，周期信号可能有多个同样合理的偏移。长文件上，滤波、数据准备和输入检查的成本也可能超过我们原本关注的相关计算。

这次研发从固定的 audioscope v1.1.8 实现出发：先建立可复现的比较，再实现自己的算子，经过五轮独立审查和一轮消融，最后重新判断哪些设计确实带来了收益。

最终，固定消融语料中的正例优势可以归到声道策略和极性支持；多候选的已测收益是拒绝周期多解；短窗口显著减少长输入开销。部分白化没有提高这组数据的成功数，却通过提前退出影响了部分素材的速度。这个结论比最初对算法的解释更具体，也更有限。

## 1. 先约定对齐的含义

设输入是相同采样率的已解码 PCM，参考信号为 A，待比较信号为 B。偏移约定为：

$$
A[n] \approx p\,B[n+d],\qquad p\in\{-1,+1\}.
$$

`d > 0` 表示 B 中对应的内容出现在更晚的位置。这里的 `p` 只描述整体极性；幅度差由后续增益拟合处理。估计延迟本身不移动、不修改任何输入样本。

原型提供两个接口：

```js
estimateAlignment(aChannels, bChannels, sampleRate, options)
// { accepted, offsetSamples, polarity, confidence, reason }

compareResidual(aChannels, bChannels, sampleRate, offsetSamples)
// 有效重叠区的共享增益、残差 RMS、峰值、相消深度等
```

前者解决“是否存在足够可信的整数偏移”，后者解决“按这个偏移比较时，还剩多少差异”。`confidence` 是相关系数绝对值，不是正确概率。

本次没有实现不同采样率之间的重采样，也没有处理亚采样延迟、时钟漂移、动态时间规整或不同演奏版本的乐曲结构匹配。两段信号必须能用一个固定整数延迟来描述。

## 2. 把对比基线固定下来

基线固定为 audioscope **v1.1.8**、提交 `0cf177499eb3d80a06e37be6efa13ed4ac10c25e`。其数学代码、原测试和 MIT 许可证都保存在实验目录的 [vendor](audio-alignment-research.md) (`dsp-lab/vendor/`) 中，来源与 SHA-256 记录在 [source.json](audio-alignment-research.md) (`dsp-lab/vendor/source.json`)。比较依据是这份源码，不是对其他版本行为的推测。

该基线先平均声道，再将最多前 60 秒降采样到约 4 kHz。通过普通互相关选一个粗峰，然后回到原采样率，在邻域内用最多 65,536 个样本精修。粗峰和精修都寻找最大的正值。

我们的实现也采用粗到细的搜索，但改变了声道准备、频谱权重、候选数量和分析窗口。双方都处理了 DC 偏置，不能把“去均值”说成我们独有的优势。

实验的生产算子位于 [operator.mjs](audio-alignment-research.md) (`dsp-lab/operator.mjs`)，FFT 位于 [fft.mjs](audio-alignment-research.md) (`dsp-lab/fft.mjs`)。它们都在独立的 `dsp-lab` 中运行。实验结果不等于已经交付了扩展内的音频对齐功能。

## 3. 第一组问题：不要在搜索前丢掉信号

### 3.1 左右声道平均可能把声音变成零

考虑一个很容易构造的立体声输入：

$$
L=x,\quad R=-x,\quad (L+R)/2=0.
$$

两个声道各自都有完整的信息，平均后却没有可用于对齐的信号。这种 Side-only 输入也会让依赖单声道混合的增益拟合失去意义。

我们的延迟估计选择一对对应声道。对每个声道，分别计算 A、B 的去均值能量，取两者较小值作为评分，再选择评分最大的声道对。这样优先使用两边都有信号的一对，而不是只看某一边谁更响。

这个评分是能量启发式，不是多声道联合匹配，也不是按相关度选声道。若某个声道包含很强的干扰，它仍可能被选中。估计出的延迟统一作用于全部声道，不分别移动左右声道。

### 3.2 负相关也可能是正确对齐

若 B 是 A 的反相延迟副本，正确位置的相关系数会接近 −1。只找正峰，可能把真正的匹配排除，转而选择旁边的正旁瓣。

因此我们用相关绝对值比较候选，用符号报告极性。负峰不再自动代表“匹配差”。这项处理也没有自动翻转文件；是否补偿极性，是未来产品层需要明确的行为。

这两个边界条件后来解释了固定语料中相对基线的全部正例差距。它们并不意味着普通同极性音频的定位精度全面领先。

## 4. 粗搜索：用短窗口产生候选

当前流程可以写成：

```text
检查 PCM → 选择对应声道 → 寻找有能量的区域
        → 截取分析窗口 → 低通并降采样
        → 加权互相关 → 最多三个粗峰
        → 原采样率精修 → 接受或拒绝
```

### 4.1 将搜索范围与计算窗口分开

默认允许 ±2 秒的偏移，并不意味着需要把整段 30 秒录音都送进粗搜索。

我们在最多前 60 秒的共同可用长度内寻找有能量的区域，然后截取：

$$
T_{\text{window}}=\max(4,\;2T_{\text{lag}}+0.5)\ \text{秒},
$$

实际窗口还受可用音频长度限制。默认窗口为 4.5 秒。再以 `floor(sampleRate / 2000)` 为抽取因子，得到约 2 kHz 的分析信号。

在 48 kHz、30 秒输入上，audioscope 每路粗信号约 120,000 点，对应 262,144 点 FFT；我们的默认窗口每路约 9,000 点，对应 32,768 点 FFT。这里比较的是 FFT 长度，不能直接当作整体八倍加速。

### 4.2 降采样前保留低通

基线用于延迟分析的降采样是分块平均。我们使用 Blackman 窗 sinc FIR：半径为四倍抽取因子，截止频率为输出 Nyquist 的 80%，然后归一化滤波核。

较长 FIR 的每个输出点更贵。它能更明确地抑制抽取时的混叠，但本次没有把滤波器选择单独消融，不能宣称准确率提升已经被归因到它。缩短处理窗口，才让这项成本保持可控。

### 4.3 部分白化的初始设想

令 A、B 的频谱分别为 X、Y，交叉频谱为：

$$
S_k=\overline{X_k}Y_k.
$$

普通互相关直接对 S 做逆 FFT。我们的粗搜索使用：

$$
C=\operatorname{IFFT}\!\left(
\frac{S_k}{\sqrt{\max(\epsilon,|S_k|)}}
\right).
$$

实现中的下限为：

$$
\epsilon=\max\left(10^{-20},\;10^{-5}\max_k |X_k||Y_k|\right).
$$

这样会减弱强频段对粗相关的支配，同时避免无限放大极弱频点。它的权重介于普通互相关与完整 PHAT 之间。

设计上的假设是：更多频段能参与定位，粗峰可能更有区分度。**这是一项待检验的假设。后面的消融没有证明它提高了本语料的准确率。**

## 5. 精修：高相关不一定意味着偏移唯一

粗搜索按相关绝对值选最多三个局部峰。每个峰附近在原采样率上逐样本搜索，邻域为峰值两侧各两倍抽取因子，并受最大允许偏移限制。

精修最多使用 16,384 个样本。对有效重叠区一次累计 `sum(A)`、`sum(B)`、`sum(A²)`、`sum(B²)` 和 `sum(AB)`，得到去均值的归一化相关系数：

$$
\rho(d)=
\frac{\sum ab-\frac{\sum a\sum b}{N}}
{\sqrt{\left(\sum a^2-\frac{(\sum a)^2}{N}\right)
             \left(\sum b^2-\frac{(\sum b)^2}{N}\right)}}.
$$

基线分两遍计算均值和中心化后的乘积；我们的原始矩统计减少了一次遍历。两者在数学上对应同一类相关系数，但浮点计算路径不同；不能把它描述为对任意输入逐字节等价的替换。原始矩形式也仍需注意极端 DC 与低方差下的数值误差。

有效重叠不足 128 个样本，或方差过低时，当前精修函数返回零相关，避免把信息不足的片段当作可靠证据。

当前接受规则是最佳 `abs(rho) >= 0.75`。若另一个不同候选的得分大于最佳值的 98.5%，则拒绝为 `ambiguous-peaks`。这是已搜索候选间的歧义检查，不保证发现全局所有多解。

周期信号能说明为什么需要它。纯音每隔一个周期就相似，多个偏移都可能得到接近 1 的相关系数。输出一个很高的分数，并没有解决“究竟该移动多少”的问题。

我们也有提前退出：当第一个候选的得分超过 0.999，且第二个粗峰低于第一峰的一半时，可以结束剩余候选精修。它是基于当前候选结构的启发式，后来成为白化影响速度的关键。

## 6. 测试不是只有“延迟副本”

测试生成器在 [corpus.mjs](audio-alignment-research.md) (`dsp-lab/corpus.mjs`)。基础信号混合了带包络的滤波噪声、变化音高的正弦成分和固定频率成分，用固定种子复现。正例覆盖：

- 正、负整数延迟与搜索范围边界；
- 增益、DC 偏置和附加噪声；
- 整体反相、Side-only、左右声道能量不等；
- 一阶低通和前导静音。

低通会改变波形，所以这个家庭允许 2 个采样点误差，其他原有家庭通常为 1 个采样点。逐例通过指标与最终验证中的“至少 95% 在 1 个采样点内”是两个检查口径，不能混为一谈。

负例包含不同噪声但共享调性结构的信号、静音、常量和周期多解。初期保存的开发结果仍有 **5/24 个负例被接受**，相关度约在 0.49–0.52。这提醒我们：有共同调性结构，不等于可以自动对齐。开发阶段调整后，最终相关阈值为 0.75；调整前的 [结果](audio-alignment-research.md) (`dsp-lab/results/dev-round-1.json`) 没有删除。

随后首次留出验证为 72/72 正例成功、32 个负例全部拒绝；基线正例为 56/72。这里“留出”描述当时的阶段。后续重复优化、消融已经使用这些输入，它们现在是固定回归语料，不再是新的盲测。

四份本地 MP3 由 macOS `afconvert` 解码为 48 kHz 双声道 Float32，取前 30 秒，再施加已知延迟、增益、极性与噪声变换。真实素材变体结果是 16/16，对比基线 12/16；差距来自四个反相案例。

这些数据使用真实音频内容，但真值来自人工施加的变换，不是两次独立录制后的人工标注。额外确认包含新种子的 52 例和六对不同录音，共 58 例，另有六组增益／残差检查；它们也不能替代真实采集误差的评估。

## 7. 增益与残差：只比较真正重叠的部分

对齐之后，用全部声道的有效重叠样本拟合一个共享增益：

$$
g^*=\frac{\sum_{c,n\in\Omega} A_{c,n}B_{c,n+d}}
           {\sum_{c,n\in\Omega} B_{c,n+d}^{2}},
\qquad e_{c,n}=A_{c,n}-g^*B_{c,n+d}.
$$

共享增益保留声道比例。它允许负值，也排除了没有对应音频的补零尾部。残差 RMS、峰值和相消深度都按这个重叠区计算。

当参考能量非零时，相消深度为参考能量与残差能量比的 `10*log10`；残差为零则返回正无穷。参考本身没有能量时，该比值没有意义，返回空值。

相比之下，基线的 `fitGain` 接收单声道输入，并限制正增益。我们的口径更适合立体声相减，但不意味着所有内容的残差都会更小；它也没有拟合 DC 偏移、频响或非线性失真。增益匹配服务于 null test，不是 LUFS 监听音量匹配。

## 8. 性能轨迹：第一版其实更慢

历史计时均保存了原始样本，而不只保留最后一次的好结果。下列倍率定义为 `基线耗时 / 原型耗时`，大于 1 才代表原型更快。

1. **第一版：** 30 秒约 0.63–0.64，3 秒约 0.57–0.59。正例改善了，实现却更慢。
2. **第二版：** 改进完整 PCM 检查、增加候选提前退出后，30 秒约 1.02–1.04，长输入接近持平；短输入仍较慢。
3. **缩短窗口与简化 FIR 边界循环后：** 两轮长输入约 1.71–1.88；短输入没有稳定收益。
4. **五轮审查后的完整版本：** 独立重复计时，长输入约 2.80–2.87，短输入约 1.33–1.38。

前两阶段见 [第一版计时](audio-alignment-research.md) (`dsp-lab/.cross-gan/baseline/timing-round-1.json`) 和 [第二版计时](audio-alignment-research.md) (`dsp-lab/.cross-gan/baseline/timing-round-2.json`)；最终两轮见 [验证结果](audio-alignment-research.md) (`dsp-lab/results/final-verification.json`)。这些阶段不是单因素实验，不能凭先后顺序给每次改动分配收益比例。

计时包括全量 PCM 有限值检查、声道准备和延迟估计，不包括解码、重采样、残差计算、IPC 或界面。上述数字不是整个音频编辑器的速度，也不是对其他机器和输入长度的保证。

## 9. 五轮审查留下了什么

五轮采用独立的候选提出者和判别者。候选必须能复现，效率改动还必须通过原有语料的输出等价与实际计时门禁。每轮发现、证伪、提交和测试都保存在 [.cross-gan](audio-alignment-research.md) (`dsp-lab/.cross-gan/checkpoint.json`)。

### 第 1 轮：稀疏样本被误判为静音

快速能量检查每隔 32 个样本取一个值。如果信号只在 `1 mod 32` 的位置非零，探针看到的就全是零。两份完全相同的非恒定音频因此被拒绝为静音。

最小构造如下，从仓库根目录执行：

```js
import { estimateAlignment } from './dsp-lab/operator.mjs';

const x = new Float32Array(48000);
let state = 7;
for (let i = 1; i < x.length; i += 32) {
  state = (Math.imul(state, 1664525) + 1013904223) >>> 0;
  x[i] = state / 4294967296 - 0.5;
}
console.log(estimateAlignment([x], [x.slice()], 48000));
```

修复不是取消快速探针，而是在它判断能量不足时，再检查完整样本。回归覆盖多个采样相位及正、负延迟，并确认真实静音和常量仍被拒绝。

### 第 2 轮：信号存在，精修窗口却落在静音中

把稀疏信号移到一秒音频的后半段，声道能量回退虽然通过了，窗口选择器每隔 16 点的能量探针仍可能漏掉它，最终选中前段静音。

这一轮给窗口选择也增加了完整采样回退。独立发现与独立复现很重要：修好“是不是静音”，不等于修好“在哪里分析”。

### 第 3 轮：尾部没有被枚举到

窗口按半个窗长移动，会留下不足一步的尾部。48,000 点输入、16,384 点精修窗，原来的起点为 0、8,192、16,384、24,576，最后只覆盖到 40,960。若有效信号位于 46,000 之后，再精细地重扫已有窗口也没用。

修复在低能量回退中额外比较末端对齐窗口。回归覆盖 8、44.1、48、192 kHz 与正负延迟；这是边界构造验证，不代表完整覆盖了整个采样率区间。

### 第 4 轮：完整检查可以更快，但不能少检查

完整 PCM 检查改为每轮顺序检查八个样本，尾部不足八个的部分仍走标量循环。没有跳过任何值，也没有省略 NaN 或正负无穷检测。

新增测试覆盖长度 1–25 的每个位置、三类非法值、两个输入、单／双声道和两个接口。原算子到最终算子的配对计时中，30 秒耗时减少约 25–27%，3 秒减少约 6–7%。

这是一项有实测收益的循环优化，不是新的对齐原理，也不能推广成所有 JavaScript 循环都应该展开。

### 第 5 轮：极小噪声绕过了严格的零值条件

若前段不是全零，而是极小背景噪声，“仅当能量等于零才回退”仍可能选中无法可靠精修的区域，漏掉尾部有效音频。最终条件改为低于 `1e-12`，与已有的声道静音阈值一致，并保留完整回退与尾部检查。

回归使用不同背景幅度、正负延迟和极性变化。每轮还比较 250 个固定案例中对齐、残差返回对象的 JSON 序列化结果，要求逐字节一致。这个保证只覆盖被测语料和该序列化表示；修复边界问题本来就会改变新增触发输入上的行为。

## 10. 两个看起来合理、最后却没保留的优化

**合并两次正向 FFT。** 两路变换可以共享位反转索引和旋转因子递推，局部测试也出现过收益。但放回完整算子，八组计时的中位倍率只有约 1.006，部分变慢，没有超出噪声的可靠收益，因此回退。

**融合两路 FIR 遍历。** 独立提出者的内存实验表现良好；实际文件中的实现却在两轮整体计时中变慢。虽然 405 组内部 Float64 缓冲区逐字节一致，第一轮短输入的倍率只有约 0.84–0.88，长输入约 0.95–0.96，仍被回退。

这里没有充分证据解释 JIT 为什么给出不同结果。能确认的是：算术量更少、内存实验更快，不足以证明真正运行的算子更快。两份失败实现和计时都保留了下来，而不是从开发轨迹中删掉。

## 11. 消融：哪些改动解释了效果

为了避免把多项设计一起包装成一个无法拆解的优势，我们冻结完整版本，分别关闭声道选择、部分白化、多候选、短窗口，并运行全部 16 种组合。另加关闭极性支持的对照和固定基线，总计 18 个版本。

语料为历史固定 250 例、新增两种子的 52 例，以及预先定义的 16 个诊断例，共 **318 例：230 正例、88 负例**。完整版本快照与算子源码相同，318 次完整返回对象均与直接调用一致。

### 11.1 准确率归因比想象中简单

- **完整版本：230/230 正例成功，88 个负例全部拒绝。**
- **关闭声道选择：204/230。** 少的 26 例都是声道相消。
- **关闭部分白化：230/230。** 负例拒绝不变，本语料未证明准确率收益。
- **关闭多候选：230/230。** 正例不变，但 22 个周期多解案例由拒绝变为接受。
- **关闭短窗口：230/230。** 未观察到本语料上的准确率损失。
- **关闭极性支持：204/230。** 少的 26 例是 22 个合成反相例和四个真实素材反相变体。
- **audioscope：178/230 正例正确。** 其 52 个失败集合，恰好等于声道策略与极性支持两项消融失败集合之并集，二者不重叠。

因此，本轮相对基线的全部正例优势都可对应到这两个边界条件；普通 178 例双方均正确。16 组合中没有观察到通过数上的准确率交互，但这不是“所有输入均不存在交互”的统计证明。

22 个周期案例还有一个容易忽略的问题：它们来自 11 个种子标签和两个采样率，但纯音公式不使用种子，实际只有两份不同采样率的波形。它们是 22 次测试，不是 22 份独立证据。

此外，单候选消融也同时移除了跨候选的歧义拒绝。我们验证的是整个“多候选精修＋歧义检查”策略，不能只把拒绝收益归给精修。audioscope 接口本身没有拒绝状态，也不能把测试包装器的 `accepted: true` 解释成它在 88 个负例上全部做错。

### 11.2 速度归因要保留条件

主计时使用四份真实素材的 3 秒和 30 秒版本，每组四次预热、21 次正式调用、三轮重复。每块轮转并反转版本顺序，在整块开始前 GC，GC 不计时。共 504 个块、3,024 次正式调用。

定义比值为“关闭项耗时／完整版本耗时”，取 12 个素材×轮次比值的中位数：

- **声道选择：** 3 秒为 1.332、30 秒为 1.447。启用后少约 25%、31% 的耗时。这个对照包含平均混合的分配和全长累计，不能把收益说成只是选声道评分更快。
- **部分白化：** 方向随素材变化。3 秒 A/C/D 关闭后约慢 35%，B 反而快约 8%；30 秒 A 关闭后约慢 12%，B/C/D 反而快约 9%。
- **多候选：** 3 秒为 1.005、30 秒为 0.997，变化约在 ±2% 范围，没有稳定提速证据。
- **短窗口：** 3 秒约为 0.998，基本不变；30 秒为 3.472，耗时约从 37 ms 降到 10.6 ms，减少约 71%。

这些是其他组件启用时的条件性差值，不能相加成总贡献，也不能再乘到相对竞品的倍率上。我们的长窗对照保留自身较长 FIR，因此甚至比基线更慢；短窗口节省的耗时可以大于相对基线的总差距。

## 12. 白化为什么有时反而更快

去掉频谱归一化应该少算一些东西，为什么部分输入却变慢了？我们在主实验后增加了运行计数。插桩版本的 40 次返回对象都与未插桩版本一致，但计数版本不参与计时。

完整配置的八组真实素材时长组合，都在第一候选后提前退出，只调用 97 次精修相关计算。关闭白化后，3 秒 A/C/D 和 30 秒 A 不再早退，升为 291 次。变慢的恰好是这些组合。

短窗口的成本差也能直接数出来：30 秒输入使用短窗时，每个 FFT 长度为 32,768，双输入 FIR 约 347 万次乘加；改用全长，分别变为 131,072 和约 2,316 万次。精修次数仍为 97，增加的主要是滤波和 FFT。

为验证白化与多候选的速度交互，我们又做了固定声道策略／短窗的 2×2 计时。这个追加分析明确标记为事后实验，没有调算法阈值。固定为单候选后，关闭白化在全部八组素材时长上均更快：3 秒约少 6–13%，30 秒约少 8–10%。

这支持一个更精确的解释：**白化本身有计算成本；部分素材的净提速来自粗峰变化后更早结束后续搜索。** 它不支持“白化提高了本语料准确率”的说法。普通精确副本也不足以衡量困难输入中完整三候选搜索的成本。

## 13. 怎样复现，而不是只引用数字

算法与测试无需额外 npm 依赖，需要 Node.js 24+。真实计时还需要本地四份素材，音频本身未进入 Git；不能假设克隆仓库就能复现真实素材计时。

从仓库根目录进入实验目录，先准备自己的 `A.mp3`–`D.mp3`：

```sh
cd dsp-lab
node prepare-audio.mjs /path/to/audio-directory
npm test
npm run evaluate

# 最终验证要求两份计时都与当前算子哈希匹配。
node --expose-gc timing.mjs
cp results/timing.json results/timing-pass-1.json
node --expose-gc timing.mjs
npm run verify
```

上述命令会更新结果。若要保留已提交的原始数字，应先另存或在单独的检出中复测。使用自有素材时，得到的时间不必与本文一致。

消融的快照与原始素材哈希已经冻结。只有使用原实验 PCM，才能通过原 manifest 的一致性检查：

```sh
node ablation/run.mjs accuracy > ablation/accuracy.log
node --expose-gc ablation/run.mjs bench > ablation/timing.log
node ablation/work-counts.mjs
node --expose-gc ablation/interaction.mjs > ablation/interaction.log
node ablation/run.mjs report > ablation/report.log
node ablation/run.mjs verify
```

消融入口不会静默重建快照：首次 `prepare` 负责冻结协议与快照，已有 manifest 时拒绝覆盖。原有测试、语料、基线、算子和 PCM 的哈希改变，会触发验证失败。这能防止拿旧结果证明新代码，也能提示复现者输入其实不同。

## 14. 当前可以说什么，还不能说什么

我们已经验证：声道相消和整体反相不能被当作普通正相关搜索的小变体；短窗能显著减少固定长输入的计算；拒绝周期多解是有用的接口行为；局部优化必须回到实际算子计时；消融会改变对收益来源的判断。

我们还没有验证：独立录音、长时间漂移、亚采样精度、强非线性、复杂频响差异，以及局部片段不能代表整段内容时的可靠性。能量选声道和提前退出都是启发式，8–192 kHz 的输入范围也不等于整个区间已经完整测过。

下一步若继续研究，优先级应是补充独立、困难、带人工真值的素材，检验白化、多候选和短窗口的边界，再决定是否简化配置。当前默认版本保持不变。
